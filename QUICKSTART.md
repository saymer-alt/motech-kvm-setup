# Быстрый старт: МосТех → Windows 10 VM

> **Статус:** восстановлено по полевым скриптам и описанию автора. Проверять на тестовом ПК; особенно сетевой мост. Не запускать вслепую на действующих рабочих местах.

## Результат
МосТех Linux и Windows 10 Pro — две отдельные доменные системы. Пользователь входит в МосТех, вручную открывает `virt-manager`, запускает Windows и переключает консоль на полный экран. Windows получает собственный IP через `br0` и управляется удалённо через **LiteManager** (не RDP).

## 0. Перед началом
- Убедиться в наличии прав администратора, свободных ресурсов и аппаратной виртуализации VT-x/AMD-V.
- Иметь законно полученный установочный ISO Windows 10 Pro, необходимые драйверы и согласованную процедуру включения VM в домен.
- Сделать резервную копию важных данных и сетевого профиля; узнать, DHCP или статический IP использует МосТех.
- **Не запускать setup-bridge.sh через SSH.** Скрипт переводит интерфейс на DHCP-мост и может оборвать корпоративную сеть.

## 1. Установка виртуализации
В каталоге клонированного проекта:

```bash
grep -Eoc '(vmx|svm)' /proc/cpuinfo
sudo bash scripts/setup-kvm-motech.sh
```

Скрипт устанавливает `qemu-kvm`, `libvirt`, `virt-install`, `virt-manager` и дополнительные SPICE/GStreamer библиотеки; предлагает выбрать пользователя, добавляет его в `libvirt` и настраивает Polkit. Затем **полностью выйти из сеанса МосТех и войти заново**.

## 2. Сеть (только локально, с планом восстановления)
```bash
sudo bash scripts/setup-bridge.sh
ip -4 addr show br0
nmcli connection show
```
Скрипт выбирает физический Ethernet и переводит его в мост `br0` с DHCP. Перед запуском изучить [ограничения сети](docs/networking.md).

## 3. Создание Windows VM
```bash
virt-manager
```
- Подключиться к системному QEMU/KVM (`qemu:///system`).
- Создать VM, выбрать ISO Windows; параметры CPU/RAM/диска подобрать для конкретного ПК (исходники их не фиксируют).
- Для сетевого адаптера VM выбрать **Bridge br0**, модель **virtio** (может потребоваться пакет гостевых драйверов).
- Установить Windows, драйверы VirtIO / SPICE по необходимости; включить Windows в рабочий домен **по корпоративной инструкции**.
- Настроить полноэкранный режим `virt-manager`; проверить вход под доменным пользователем.
- Настроить **LiteManager** штатным способом организации.

## 4. Проверка
На хосте: `ip -4 addr show br0`, `virsh -c qemu:///system list --all`.
В Windows: `ipconfig /all`. Удостовериться, что адрес Windows отличается от адреса МосТех, находится в нужной сети и доступен корпоративным службам. Проверить управление через LiteManager.

Гостевые компоненты и официальные ссылки: [docs/windows-guest.md](docs/windows-guest.md).

## Важно
Оригинальная Windows-конфигурация содержала реальный пароль: **не использовать/не публиковать исходный XML**, считать пароль скомпрометированным и заменить на затронутых машинах. Здесь опубликован только обезличенный пример.
