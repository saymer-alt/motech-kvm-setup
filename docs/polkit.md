# Управление libvirt доменными пользователями

Цель — пользователь входит в доменную учётную запись МосТех и вручную запускает свою Windows VM через `virt-manager`, без постоянных административных запросов.

Исходный установщик:
- определяет пользователя (через `SUDO_USER`, `who`, `loginctl`, `last` и локальные учётные записи);
- проверяет наличие пользователя с `id`;
- добавляет его в локальную группу `libvirt`;
- устанавливает для сокета libvirt группу `libvirt`, права `0770`, `auth_unix_rw = "polkit"`;
- создаёт правило Polkit, разрешающее `org.libvirt.unix.manage` для всей группы `libvirt`;
- перезапускает службы `polkit` и `libvirtd`.

**Важное предупреждение:** разрешение `org.libvirt.unix.manage` всей группе `libvirt` — широкий привилегированный доступ к системной виртуализации, не только старт/стоп одной VM. Предоставлять только доверенным пользователям и согласовать с корпоративной политикой. Не использовать `auth_unix_rw = "none"`.

После добавления в группу надо полностью завершить пользовательский сеанс и войти заново. Затем проверить:

```bash
id
virsh -c qemu:///system list --all
virt-manager
```

Если пользователь указан в домене через SSSD, его фактическое имя нужно проверять `id`/`getent passwd`; не предполагать, что короткое имя всегда подходит. Старый файл `Polkit.txt` был привязан к конкретной учётной записи организации; здесь намеренно нет персональных имён.

**Долг:** реализовать избирательное разрешение операций только для нужных VM, проверить совместимость с доменными именами, исключить неоднозначное восстановление имени пользователя из `last`.
